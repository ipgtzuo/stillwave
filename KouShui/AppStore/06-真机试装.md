### 2) 连手机
- USB 线连上 Mac，解锁 iPhone，弹窗点 **「信任此电脑」**。
- `iPhone → 设置 → 隐私与安全性 → 开发者模式`：这台机器已是 enabled，若换设备需打开并重启。
- 确认 Xcode 顶部设备列表里能选到 **iPhone 15 Pro Max**（不是 `Any iOS Device`、不是 Simulator）。

### 3) 改 Bundle ID（**别只改 Signing 面板**）
当前是占位 `com.example.koushui` / `com.example.koushui.watch`，建议换成自己的反向域名，例如 `com.zuog.koushui`。

⚠️ 本工程把 ID 做成了**工程变量**：两个 target 的 `PRODUCT_BUNDLE_IDENTIFIER` 分别引用 `$(IOS_BUNDLE_ID)` / `$(WATCH_BUNDLE_ID)`，而 `WatchApp/Info.plist` 的 `WKCompanionAppBundleIdentifier` 也引用 `$(IOS_BUNDLE_ID)`。
如果只在 Signing 面板里把字面 Bundle Identifier 改掉，Watch 的 companion 仍指向 `com.example.koushui`，会出现 companion 不匹配 / 装不上的诡异问题。正确改法是二选一：

- **A（推荐）**：`project.yml` 里改这两行，然后 `xcodegen generate`（没装 XcodeGen 就走 B）：
  ```yaml
  IOS_BUNDLE_ID: com.zuog.koushui
  WATCH_BUNDLE_ID: com.zuog.koushui.watch
  ```
- **B**：Xcode 里选 **Project（不是 Target）→ Build Settings → User-Defined**，把 `IOS_BUNDLE_ID` 与 `WATCH_BUNDLE_ID` 改成新值；Debug / Release 两组配置都要改。

> 用第 3 节的命令行脚本则不用改文件，脚本会通过 `IOS_BUNDLE_ID=… WATCH_BUNDLE_ID=…` 覆盖这两个变量，Watch plist 同步生效。

### 4) Run
- 打开工程：`open KouShui/KouShui.xcodeproj`
- 两个 target → `Signing & Capabilities` 保持 **Automatically manage signing**；Team 已由工程预置（`G.T. Zuo (Personal Team)`），无需手选。若还显示旧报错，关掉工程重新打开让它重读 pbxproj。
- scheme 选 **Stillwave**，destination 选 **iPhone 15 Pro Max**，按 **▶ Run**。
- 首次会同时签 iOS App 与内嵌 Watch App，装完自动启动。手机主屏会出现「叩音」图标（顺便检查浅色壁纸下的图标）。
- 免费签名 **7 天有效**，过期后在 Xcode 再 Run 一次即可。

## 2. Watch 端真机（这才是本项目的核心体验）

- 手表与 iPhone 保持配对、蓝牙开、同 Wi-Fi、手表解锁。
- iOS App 安装后，Watch App 通常会自动同步；若表盘上找不到：iPhone 打开 **Watch App → 我的手表 → 已安装 App → 叩音 → 显示/安装**。
- 也可在 Xcode 里把 scheme 切成 **KouShuiWatch**、destination 选配对的手表（显示为 `… via iPhone`）后 Run。免费账号首次给手表签名，若提示设备未注册，去 `Window → Devices and Simulators` 选中手表让它自动注册。
- 表端默认是**静音**的：不弹「请戴耳机」，曲调由最轻触觉的疏密承载；开 `WKExtendedRuntimeSession(.mindfulness)` 后熄屏继续。想听声音要在表端设置里主动开。

### 真机上要重点验的 5 件事（模拟器给不了）
1. iPhone 四种材质的 Core Haptics 手感：`attackTime / decayTime / intensity / sharpness` 是否真的「温柔」而不是「嗡一下」。
2. 五音 + 加权旋律游走在连续敲时是否仍有曲调，不吵、不累。
3. 表端熄屏后触觉是否还在；勿扰 / 静音态是否按设计静默跳过。
4. 「水在回想」在完全无声时是否仍可感知。
5. 连续敲 5 分钟的耗电与发热；图标在主屏与表盘圆裁切下的观感。

把结果告诉我，我按真机反馈调参数（尤其第 1、3 条）。

## 3. 命令行一键（可选，我可以帮你跑）

```bash
cd KouShui
./scripts/install-device.sh            # 零参数即可，Team 自动推断为 9RH9WL3PQ3
# 也可显式指定：
./scripts/install-device.sh [TEAM_ID] [DEVICE_UDID] [BUNDLE_PREFIX]
# 例：
./scripts/install-device.sh 9RH9WL3PQ3 00008130-000059DC1151001C com.zuog.kouyin
```

脚本会依次：自动推断 Team ID（Xcode 偏好 `teamID` → 证书 Subject 的 `OU` → 描述文件 `TeamIdentifier`，都取不到就用工程里固化的值）→ 真机 arm64 编译（`-allowProvisioningUpdates` 自动注册设备 / 建 App ID / 生成描述文件）→ 校验签名与内嵌 Watch App → `devicectl` 安装 → 启动。
> 命令行 `xcodebuild` 读的是钥匙串里的账号凭据，缺 `Xcode-Username` 时会报 `No Accounts`（03:00 非沙箱实测也一样）。**以 Xcode GUI 的 ▶ Run 为准**；GUI 装好后就不必再跑脚本。

## 4. 排错速查

| 报错 | 处理 |
|---|---|
| `Signing for "Stillwave" requires a development team` | 工程已固化 `DEVELOPMENT_TEAM = 9RH9WL3PQ3`（02:59 修）；若 Xcode 里还显示，关掉工程重新打开让它重读 pbxproj，或在 Signing 面板选 `G.T. Zuo (Personal Team)` |

| `Failed to load credentials … missing Xcode-Username` | 同上，凭据条目不完整；重新登录会重建，不要手工改钥匙串 |
| `No account for team YT278M5BQ5` | 把 Personal Team 的 member ID 误当成 Team ID；正确值 `9RH9WL3PQ3`，脚本已修 |
| `The app identifier "com.example.koushui" cannot be registered` | 占位 ID 冲突 → 按第 1 节第 3 步换成自己的反向域名 |
| `device is not registered` / 安装时找不到设备 | `Window → Devices and Simulators` 里选中手机让它自动注册；确认已解锁并信任 |
| `Developer Mode disabled` | 设置 → 隐私与安全性 → 开发者模式 → 打开并重启 |
| `Verify that the Developer App certificate … is trusted` / 装好后图标点不开 | **当前这一步**：iPhone → 设置 → 通用 → VPN 与设备管理 → 开发者 App → 点 `Apple Development: …` → 信任 → 再确认信任。03:08 实测 App 已装好，只差这一步 |
| `FBSOpenApplicationServiceErrorDomain error 1 … profile has not been explicitly trusted by the user` | 同上，命令行启动失败的系统原文；点完信任后 `devicectl device process launch --device <UDID> com.example.koushui` 应能成功 |
| `A signed resource has been added or modified` | 清 DerivedData 后重编（脚本用 `/tmp/koushui-device-dd`） |
| Watch App 装不上 / companion 报错 | 检查 Watch plist 的 `WKCompanionAppBundleIdentifier` 是否等于 iOS 实际 Bundle ID（本工程用变量联动，别写字面量） |
| 7 天后 App 打不开 | 免费 Personal Team 签名过期，重跑一次即可 |
