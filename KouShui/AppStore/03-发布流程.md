# 发布流程 · 从工程到 App Store

> 本工程的 `KouShui.xcodeproj` 已在本机 **Xcode 27.2 / iOS 27.2 / watchOS 27.2 SDK** 下双端 `BUILD SUCCEEDED`、0 warning。
> 下面是把这份工程送上线要走的每一步。带 TODO 的必须替换。

---

## 0. 本机已验证的构建命令（可直接复用）

```bash
cd KouShui

# 如果改过 project.yml，先重新生成工程（需要 xcodegen；不改则跳过）
xcodegen generate

# iOS scheme（会连带编译并嵌入 Watch App，各 target 用自己的 SDK）
xcodebuild -project KouShui.xcodeproj -scheme Stillwave \
  -destination 'generic/platform=iOS Simulator' -configuration Debug \
  CODE_SIGNING_ALLOWED=NO -derivedDataPath /tmp/koushui-dd build

# 单独编 Watch（-target 不能与 -derivedDataPath 同用，改用 SYMROOT）
xcodebuild -project KouShui.xcodeproj -target KouShuiWatch -sdk watchsimulator \
  -configuration Debug CODE_SIGNING_ALLOWED=NO ONLY_ACTIVE_ARCH=NO \
  SYMROOT=/tmp/koushui-watch-sym build
```

⚠️ 不要用 `-sdk iphonesimulator` 去编整个 scheme：该参数是全局的，会把嵌入的 watchOS target 也强行用 iOS SDK 编译，图标与 CoreHaptics 都会报错。让 destination 决定平台即可。

## 2. 账号与 App Record

1. 加入 Apple Developer Program（个人 / 组织，年费；组织需邓白氏编码，审核要额外时间，**提前办**）。
2. App Store Connect → 我的 App → `+` → 新建 App：
   - 平台 **iOS**（只建一个 App Record，不要给 Watch 单独建）
   - 名称：叩音 / Stillwave（先查重）
   - 主要语言：简体中文
   - Bundle ID：选第 1 步注册的那个（iOS 端）
   - SKU：自定义唯一串，如 `KOUYIN-2026-001`
3. **Bundle ID 注册**：Developer → Certificates, Identifiers & Profiles → 注册 iOS App ID 与 Watch App ID（Xcode 自动签名可代劳）。
4.  agreements / 税务 / 银行业务：即使免费 App，也要在 ASC 里把「付费 App 协议」状态变成有效，否则无法发布。

### 双端分发的正确口径（之前说错过，这里纠正）

Apple 官方《通用购买》：
> 「配套有 iOS App 的 watchOS App 已与 iOS App 包含在同一个 Xcode 项目中，因此你**无需**将其添加至通用购买。仅支持 Apple Watch 的 App **不能**加入通用购买。」

所以：
- **不需要 Universal Purchase**。Watch App 随 iOS App 同一个构建上传、同一个 App Record 分发，用户下载一次两端都有。
- Universal Purchase 只在以后做 **macOS / tvOS / visionOS** 版本时才需要（那时共享 bundle ID 并 Add Platform）。
- Watch 端勾了 `WKSupportsRunningWithoutiOSAppInstallation = true`，含义是「用户可不装 iPhone 端、直接在表上安装」，**不等于**要单独建 App Record。
- Watch 的截图、描述等在 ASC 的 **Apple Watch 标签页**单独维护。

## 3. 打包与上传

1. Xcode 打开 `KouShui.xcodeproj`，选 **Stillwave** scheme，目标设为 **Any iOS Device (arm64)**。
2. Product → Archive。归档里必须能看到 `Stillwave.app` 与嵌入的 `KouShuiWatch.app`。
3. Organizer → Distribute App → **App Store Connect** → Upload，一路默认（勾 Upload dSYM、不勾 bitcode 相关旧项）。
4. 等 10–30 分钟，构建出现在 ASC → TestFlight → iOS 构建列表；若卡在「缺少合规 / 无效二进制」，看邮件里的具体 ITMS 错误。
5. 常见上传错误：Watch App 缺图标、Info.plist 里 `WKBackgroundModes` 值写错、两个 target 版本号不一致、`PrivacyInfo.xcprivacy` 未打进包。
6. **已在本机模拟器验证过的一个硬坑**：Watch App 的 Info.plist 必须同时有 `WKApplication = true` 与 `WKCompanionAppBundleIdentifier = <iOS bundle ID>`。缺任一个，`installd` 会直接拒绝整个 iOS 包（「无法安装」），真机同样如此。本工程已设好，且把 companion 值做成工程变量。

## 4. 填元数据（对着 `metadata.json` 与 `01-商店文案.md`）

- App 信息：名称、副标、分类（Health & Fitness / Lifestyle）、年龄分级 4+。
- 两个本地化（zh-Hans / en-US）：描述、关键词、宣传文本、支持 URL、隐私政策 URL。
- **iPhone 截图**与 **Apple Watch 截图**分别上传（规格与构图见 `05-截图脚本.md`）。
- App 审核信息：备注（粘贴 `02-审核与隐私.md` 里的整段）、联系人、附 15 秒演示录屏。
- 定价：免费，所有国家/地区；不创建 IAP。
- 版本发布方式：建议先 **手动发布**，审核通过后自己选时间点。

## 5. TestFlight → 提审 → 发布

1. **内部测试**：团队最多 100 人，上传即可测，无需 Beta 审核。重点测三件事：
   - Watch 熄屏后触觉是否还在、勿扰时是否静默跳过；
   - iPhone 四种材质的 Core Haptics 手感（模拟器没有触觉，必须真机）；
   - 「水在回想」在静音态是否仍可感知。
2. **外部测试**（可选）：最多 10,000 人，首次需 Beta 版审核（约 1 天）。适合发预览给种子用户。
3. 提审前自检：隐私 URL 200 / 截图与构建一致 / 无疗效文案 / 名称查重 / 两个图标都在 / 审核备注写了体验步骤。
4. 提交审核。通常 24–48 小时；若被拒，按 `02-审核与隐私.md` 的对照表改，回复时逐条说明。
5. 通过后**手动发布**；如需降低风险可用 **分阶段发布**（7 天按 1%/2%/5%/10%/20%/50%/100% 放量），期间可随时暂停。
6. 发布后 24 小时：看崩溃率、评分、评论关键词、Watch 端是否被单独提及。

## 6. 回滚与下架

- **不能回滚到旧构建**：只能提交新版本修，或临时从销售下架（下架会影响评分与搜索权重，谨慎）。
- 分阶段发布可以「暂停」，这是唯一低风险的紧急刹车。
- 若发现文案合规问题，可**不发版**直接改宣传文本；名称/副标/描述改了需要新版本或走 ASC 的元数据更新。
